# R7: 뷰어를 Skia로, Direct2D 제거 — 설계

2026-11-24 작성. 사용자: "일단 넘어가보자"(R6의 그림 판단 세 가지를 미루고 다음으로). [R6 설계](2026-11-19-r6-skia-backend-design.md) 6절의 R7 행("`IRenderer`에 클립·이미지, 직접 그리기 이전, 뷰어를 Skia 표면으로, D2D와 `S100Engine` 제거")을 구체화한다. 지침 24(Skia 단일 백엔드), R6 결정 6(D2D는 Windows용으로도 남기지 않는다).

**상태: R7-0(전제 확인)은 끝났다. 2026-11-24 사용자: "너가 알아서 계속 진행해봐, skia될때까지. 중간에 정말 결정할 수 없는 게 있을 때만 물어봐" — 5절은 그 위임으로 정했다. 진행은 7절에 적는다.**

## 1. 출발점

- Skia 백엔드는 KOR TDS 808개 셀의 인스트럭션 여섯 종류를 모두 그린다(Windows, Linux). Windows에서 clang-cl로 빌드한 Skia는 CPU만으로 D2D보다 빠르다(808개 셀 22.5 s 대 D2D 소프트웨어 32.2 s, 어댑터 49.8 s — R6 8.8).
- **R6의 그림 판단 세 가지는 미뤘다**(전방위 등화의 원, 글자의 진하기, 선 스타일의 굵기). 지금 값(원으로 그린다, 회색조 + 최대 대비, 1픽셀)으로 간다. 뷰어가 Skia로 그리게 되면(R7e) 화면에서 실제로 보고 정한다 — PNG를 나란히 보는 것보다 판단하기 쉽다. 그때까지 R6는 "측정 완료, 판정 보류"다.
- 뷰어(`OpenS100.exe`)는 아직 전부 Direct2D·GDI·GDI+로 그린다.

## 2. 조사: 뷰어가 지금 그리는 길

### 2.1 프레임

- `CGISLibraryApp`이 `ID2D1DCRenderTarget` 하나를 만든다(B8G8R8A8, 알파 무시). 뷰어는 소프트웨어/어댑터를 고르지 않는다(기본 = 어댑터). `Clear`는 아무도 부르지 않는다 — 흰 바탕은 GDI(`FillSolidRect`)가 칠한다.
- **지도 패스**(`MapRefresh()`가 요청했을 때만): `map_dc`를 희게 칠하고 `gisLib->Draw(hdc)` → `LayerManager::Draw`: ① 배경(세계 지도 셰이프파일, GDI) ② 레이어 컨테이너(System Database 해도, 교환 세트 — 안쪽에 `LayerManager`가 또 있다) ③ S-100 데이터셋 ④ S-100이 아닌 것(GDI). 이어서 `gisLib2->Draw`, 수심 표시 문구(GDI `TextOutW`).
- S-100 데이터셋은 최상위에서 레이어마다 **프레임 둘**로 그린다: 우선순위 0~3, (격자 레이어들 — 각자 제 프레임), 우선순위 4~100. 프레임마다 `BindDC`·`BeginDraw`·`EndDraw`.
- **매 `OnDraw`**: `map_dc` → `mem_dc`로 `BitBlt`, 그 위에 확대 상자(GDI)·선택 강조(GDI+와 D2D)·격자 선택 보고(GDI), `mem_dc` → 화면. 끌어서 옮기는 동안은 지도를 다시 그리지 않고 `mem_dc`를 어긋나게 찍는다.

### 2.2 `IRenderer`를 거치지 않는 그리기

| 어디 | 무엇 | 쓰는 것 |
|---|---|---|
| `DepthSuppression` | S-98 D-1: S-102 자료가 덮는 곳의 S-101 수심 피처를 가린다 | D2D 레이어 + 기하 마스크(짝홀) |
| `CoverageDataset` | S-102/S-104/S-111 격자(위도 띠별 비트맵, 극에서는 한 장), 경계선·안전 등심선(대시), S-111 화살표(SVG 기하 직접) | D2D 비트맵(최근접), 선, 사용자 대시, 제 프레임과 장치 손실 처리 |
| `S100ExchangeCatalogue` | 데이터셋 경계 상자(빨강), 파일 이름·축척 글자(상자에 맞춰 크기를 줄인다) | D2D 기하, DirectWrite 레이아웃(서체 이름·굵기 지정) |
| `S100EditRender` | 꼭짓점 손잡이(사각형) | D2D |
| `OpenS100View` 선택 강조 | 점·선: GDI+ 빨간 펜. 면: D2D로 0.7 불투명 채움 | GDI+, D2D, `D2DGeometryCache` |
| `OpenS100View` 그 밖 | 확대 상자, 수심 표시 문구, 격자 선택 보고(십자·상자·글자) | GDI |
| `LayerManager::DrawInformationLayer` | 렌더러 없는 격자에 이름 상자 | GDI+ |
| `GdiGeometryRenderer`(`SHPFile`) | 배경 세계 지도, S-100이 아닌 레이어 | GDI |
| `OpenS100View::Setting` | 설정 대화상자의 서체 목록 | DirectWrite(그리기는 아님) |

**쓰이지 않는 것**(지우면 된다): `CGISLibraryApp::DrawS100Symbol`·`DrawScaleBar`(호출이 주석), `ExchangeCatalogue::DrawCoverage`, `S100LayerPortrayal::DrawInfo`, `D2D1Resources::DrawRect`·`DrawD2Rect`, `S100Utilities::GetColorNum`, `S100Engine`의 `BackgroundLayer`·`BackgroundSHPFile`·`SHPPoint`·`SHPPolygon`, `DrawInformationLayer`의 두 오버로드.

### 2.3 `S100Engine`에서 살아야 하는 것

`S100Engine`은 그리기 캐시(SVG 기하, WIC 타일, 브러시)이면서 **포트레이얼 카탈로그의 자원 저장소**(`S100PCManager` = `Portrayal::ResourceStore`: 색 프로파일, 심벌·선 스타일·면 채움 목록)다. 그리기 쪽은 R6에서 중립 코드(`SymbolPicture`·`PatternTile`·`LineStylePicture`·`ColorPalette`)가 이미 대신한다. 남는 일은 자원 저장소 자리를 중립 구현으로 바꾸는 것이다 — CMake 빌드는 이미 `S100Engine` 없이 돈다(그쪽의 저장소 구현을 Visual Studio 빌드도 쓰게 한다).

### 2.4 `IRenderer`에 없는 것

| 필요 | 쓰는 곳 | 안 |
|---|---|---|
| 클립(경로, 짝홀) | 수심 가림 | `PushClip(path)` / `PopClip()`. Skia는 `clipPath`, D2D는(남아 있는 동안) 레이어 |
| 이미지 | 격자 | `DrawImage(픽셀 BGRA 프리멀티플라이, 크기, 원본 사각형, 대상 사각형)` — 최근접 샘플링, 변환을 따른다 |
| 서체 이름·굵기, 글자를 상자에 맞추기 | 교환 카탈로그 | `TextFont`에 굵기를 더한다. 맞추기는 `MeasureText`로 호출 쪽이 한다. 서체 이름은 두지 않는다(표시 서체 하나) |
| 대시 끝 모양 | S-98 경계선 | `Stroke`에 끝 모양(둥근/평평한)을 더한다 |
| 불투명도 | 선택 강조, 심벌 | 이미 `ColorF`의 알파로 된다 |

프레임 제어(대상에 묶기, 시작·끝, 지우기)는 인터페이스에 넣지 않는다 — 표면은 응용 프로그램의 것이다(R6 3.1).

## 3. 설계

### 3.1 그리기 함수는 `HDC`가 아니라 `IRenderer`를 받는다

`LayerManager::Draw(HDC&, int)`에서 `Layer::Draw`·`SpatialObject::Draw`까지 내려가는 `HDC`를 `IRenderer&`로 바꾼다. 프레임은 하나다: 지도 패스 전체가 한 표면에 한 번(지금은 레이어마다 둘, 격자마다 하나). 순서(0~3, 격자, 4~100)는 그대로 둔다.

### 3.2 뷰어의 표면

지도 패스는 Skia 래스터 표면에 그리고, 그 픽셀을 지금의 `map_dc`(DIB로 바꾼다)가 쥔다. `OnDraw`의 `BitBlt` 구조와 끌어 옮기기는 그대로다. 위에 얹는 것(확대 상자, 선택 강조, 보고)도 `mem_dc`를 감싼 Skia 표면에 `IRenderer`로 그린다 — GDI+가 빠진다.

GPU 표면은 R7의 마지막 단계로 미룬다(5절 1).

### 3.3 서체

라이브러리는 서체 파일을 받는다(R6 3.3, 시스템 서체를 찾지 않는다). 뷰어는 설정의 표시 서체 이름을 파일로 바꿔 넘겨야 한다. Windows의 Skia에는 DirectWrite 서체 관리자가 들어 있으므로(`SkFontMgr_New_DirectWrite`) 뷰어 쪽 코드(`OpenS100/`)에서 이름으로 `SkTypeface`를 얻어 `SkiaFonts`에 넣는 길을 더한다 — 라이브러리의 `SkiaFonts`에 "이미 만든 서체를 더한다"가 생긴다. 설정 대화상자의 서체 목록도 같은 관리자로 채운다.

### 3.4 Visual Studio 솔루션과 Skia

지금 솔루션은 Skia를 링크하지 않는다(R6 8.2: 솔루션을 빌드하는 모든 사람이 Skia를 빌드하게 되므로 미뤘다). 뷰어가 Skia로 그리려면 링크해야 한다. `vcpkg.json`의 `render-skia` 기능을 솔루션의 매니페스트 설치에 켠다. 처음 빌드에 Skia 6분과 LLVM 내려받기가 든다(바이너리 캐시가 있으면 한 번).

### 3.5 전환기: 두 백엔드를 나란히

R7a~R7d 동안 뷰어는 D2D로 그리고, 옮긴 그리기는 `IRenderer`를 받으므로 D2D 백엔드에도 클립·이미지를 구현해 둔다(지침 24의 "최소한" — 새 연산 둘과 `Stroke`·`TextFont`의 새 필드뿐). R7e에서 뷰어에 백엔드를 고르는 스위치(환경 변수)를 두고 같은 화면을 두 백엔드로 본다. 사용자가 확인하면 R7f에서 D2D를 지운다.

## 4. 단계

| 단계 | 내용 | 끝났다는 것 |
|---|---|---|
| **R7-0** ✔ | 전제 확인: 중립 프레임(테스트·Skia가 쓰는 것)이 뷰어의 프레임과 같은 그림을 내는가 | 7.1절 |
| **R7a** | `IRenderer`에 클립. 수심 가림을 중립 코드로(`DrawingStages`의 구현이 `IRenderer`만 쓴다). Skia와 D2D에 구현 | S-101 + S-102를 함께 연 그림이 D2D에서 그대로, Skia에서도 가려진다 |
| **R7b** | `IRenderer`에 이미지, `Stroke`에 끝 모양. 격자(S-102/S-104/S-111)의 그리기를 `IRenderer`로. S-111 화살표는 `SymbolPicture`로 | 격자 샘플 그림이 D2D에서 그대로, Skia로도 나온다 |
| **R7c** | 교환 카탈로그의 상자와 글자, 편집 손잡이, 선택 강조, 이름 상자, 확대 상자, 수심 표시 문구, 격자 선택 보고를 `IRenderer`로. `TextFont`에 굵기 | 뷰어에서 각 기능이 전과 같이 보인다(사용자 확인) |
| **R7d** | 배경 세계 지도와 S-100이 아닌 레이어(`GdiGeometryRenderer`)를 `IRenderer`로 | 위와 같음 |
| **R7e** | `Draw`가 `IRenderer`를 받는다(프레임 하나). 솔루션이 Skia를 링크. 뷰어에 백엔드 스위치, Skia 표면, 서체 | 뷰어가 Skia로 그린다. **사용자가 화면에서 확인**(R6의 세 가지 판단 포함) |
| **R7f** | D2D 제거: `D2DRenderer`, `D2D1Resources`, `D2DGeometryCache`, `S100Engine`(자원 저장소는 중립 구현으로), GDI+, 쓰이지 않는 것(2.2). `IRenderer`에서 `DrawSymbol`·`StrokeLineStyle`·무늬 `Fill`을 내린다(R6 3.2의 약속) — 공용 코드가 직접 부른다 | 솔루션에 `d2d1`·`dwrite`·`gdiplus`가 없다. 테스트 통과 |
| **R7g**(선택) | GPU 표면(5절 1) | 프레임 시간을 재고 정한다 |

각 단계는 테스트 통과 뒤 커밋하고, 그림이 바뀌는 단계는 808개 셀로 전후를 비교한다.

## 5. 결정 (2026-11-24, 위임받아 정함)

1~3은 권고대로. 4는 **뷰어 전환을 먼저** 한다: S-100 벡터 그리기를 스위치 뒤에서 Skia로 바꾸고(4절의 R7e를 앞당긴 것, 아래 "R7v"), 그 뒤에 격자·교환 카탈로그·배경을 옮긴다. 전환기에는 Skia가 그린 층을 투명한 표면에 그려 지금의 `HDC` 위에 알파 합성한다 — D2D·GDI로 남은 것들과 순서를 지키며 섞인다. `Draw`가 `IRenderer`를 받는 한 프레임 구조(3.1)는 남은 것을 다 옮긴 뒤에 한다.

1. **CPU 먼저, GPU는 나중**(권고). R6 결정 7은 "뷰어는 GPU를 기본으로, CPU로 물러선다"였지만 그것은 MSVC로 빌드한 Skia가 느리던 때의 판단이다. clang-cl 빌드는 CPU만으로 D2D보다 빠르다. GPU 표면은 Skia 포트의 기능(`gl`이나 `direct3d`·`vulkan`)을 더 켜야 하고 장치 손실·컨텍스트 관리가 따른다. R7e까지 CPU로 가고, 실제 화면(4K, 여러 셀)에서 느리면 R7g를 한다.
2. **솔루션이 Skia를 링크한다**(권고: R7e에서). 솔루션을 빌드하는 모든 사람이 처음 한 번 Skia를 빌드한다.
3. **뷰어의 서체는 시스템 서체를 이름으로**(권고: 3.3). 라이브러리는 그대로 파일만 받는다.
4. **단계의 순서**(권고: 표대로 a → f). 다른 길: R7e(뷰어 전환)를 먼저 해서 S-101만이라도 Skia 화면을 일찍 보고, 격자·교환 카탈로그·배경은 그 뒤에 옮긴다 — 그림 판단을 일찍 할 수 있지만 그동안 Skia 뷰어에는 격자와 배경이 없다.

## 6. 위험과 모르는 것

- **프레임을 하나로 합치면 그림이 달라질 수 있다.** 지금은 레이어마다 프레임이 둘이고 격자는 제 프레임이다. D2D에서는 프레임 경계가 그림을 바꾸지 않아야 하지만 재 보지 않았다.
- **격자의 성능.** 큰 S-102를 CPU로 최근접 확대하는 비용은 재지 않았다.
- **S-111 화살표의 SVG**가 `SymbolPicture`의 범위(R6 8.3) 안인지 확인하지 않았다.
- **곡선 억제 플래그.** `SuppressSharedCurves`가 곡선에 세운 `suppress`를 되돌리는 `S101Cell::InitCurveSuppression`은 정의만 있고 호출이 없다. 보이는 범위가 바뀌어 짝이 화면 밖으로 나가도 플래그가 남는지(선이 사라지는지) 확인하지 않았다. R7과 무관하게 있던 것이다.
- **D2D 쪽의 붓 불투명도.** `D2DRenderer`는 색만 정하고 불투명도는 뷰어의 단계 훅이 1로 되돌린다. 훅 없는 프레임에서는 심벌이 남긴 불투명도가 다음 그리기에 묻을 수 있다(7.1의 비교에서는 드러나지 않았다). D2D와 함께 사라진다.
- 미확인으로 넘어온 것: macOS, CI, Skia 백엔드의 단위 테스트(솔루션이 Skia를 링크하면 쓸 수 있다), 이탤릭·대체 서체.

### 7.1 중립 프레임과 뷰어의 프레임이 달랐던 까닭

R6f에서 본 차이(808장, 다른 픽셀 중앙값 0.06%, 최대 1.7%)는 둘이 겹친 것이었다.

1. **테스트가 캔버스를 지우지 않았다.** 뷰어 방식 테스트(`RenderCell`)는 같은 캔버스에 다섯 프레임을 그리고 다섯째를 저장했다. 프레임은 지우지 않으므로(흰 바탕은 뷰가 GDI로 칠한다) 자료 바깥의 흰 바탕 위에 있는 글자와 안티에일리어싱된 가장자리가 다섯 번 겹쳐 진해졌다. 차이의 대부분이 이것이다(`101KR004F2K30`: 1.73% → 0.01%). 뷰어의 실제 화면은 프레임마다 희게 칠하므로 이 그림이 틀린 쪽이었다 — **R6f에서 Skia와 대조한 "뷰어의 그림"과 기준 그림(`base_sw`)에도 이 겹침이 들어 있었다.**
2. **광선이 변환을 정하지 않았다.** 뷰어의 단계 훅(`D2DStages::EndAreasAndLines`)은 선을 다 그린 뒤 변환을 항등으로 되돌린다. `DisplayListPainter`의 광선(등화 구역의 다리, 도등선)은 장치 픽셀로 선을 그으면서 변환을 정하지 않아 그 되돌림에 기대고 있었다. 훅 없이 도는 프레임 — R6의 단계별 D2D 기준 그림과 **Skia의 그림 전부** — 에서는 광선이 앞의 선이 남긴 세계 변환을 거쳐 화면 밖에 그려졌다. 즉 **R6의 Skia 그림에는 같은 우선순위에 선이 있는 광선이 빠져 있었다.** 광선이 `renderer.SetTransform({})`을 부르게 고쳤다(공용 코드, 한 줄).

고친 뒤 808개 셀에서 뷰어의 한 프레임과 중립 프레임의 그림은 바이트 단위로 같다. 즉 **수심 가림(S-102가 열려 있을 때)을 빼면, 뷰어가 S-100 벡터 데이터를 그리는 것은 중립 프레임 그대로다** — Skia로 바꿔 끼울 때 뷰어 쪽에서 따로 옮길 처리가 없다. 피처 켜기/끄기는 모으는 단계의 걸러내기라 그대로 따라온다.

R6 8.6의 "뷰어의 그림 대 Skia" 수치(중앙값 1.226%)는 겹쳐 진해진 뷰어 그림과 광선이 빠진 Skia 그림 사이의 것이다. 둘 다 바로잡은 뒤의 수치는 7절의 다음 행에 적는다.
