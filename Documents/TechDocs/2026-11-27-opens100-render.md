# opens100-render: 작업 파일 하나로 그림을 그리는 콘솔 프로그램 (2026-11-27)

- 상태: 첫 판 완료. Windows(포트 설치본)·Linux(트리 안 빌드)에서 확인. macOS 미확인.
- 지침: 1(라이브러리), 18(전 플랫폼), 21(Skia 단일 백엔드).
- 쓰는 법의 기준 문서는 [`apps/render/README.md`](../../apps/render/README.md)(영문)다. 이 문서는 왜 만들었는지, 어떻게 만들었는지, 무엇이 남았는지를 적는다.

## 1. 왜

라이브러리만 있고 누구나 돌릴 수 있는 프로그램이 없었다. 뷰어는 Windows(MFC)뿐이고, `examples/view`의 `opens100_view`는 데이터 전체를 화면에 맞추는 것만 한다(위치·축척·표시 설정을 못 준다).

- 다른 플랫폼에서 "되는가"를 명령 한 줄로 확인할 수단이 필요하다.
- 같은 인자로 그린 그림을 플랫폼끼리, 커밋끼리, `opens100-web`과 비교할 수단이 필요하다.
- 인자가 많다(카탈로그, 데이터셋, 위치, 축척, 팔레트, 표시 범주, 컨텍스트 파라미터 ...). 명령줄 옵션으로 늘어놓지 않고 **JSON 작업 파일 하나**로 받는다. 형식이 문서로 고정되어 있으면 사람이 아니라 AI가 작업 파일을 써서 돌릴 수 있다.

화면에 띄우는 것은 범위가 아니다. 그림 파일을 쓴다.

## 2. 무엇

`apps/render/main.cpp` 하나. 타깃 `opens100-render`.

```
opens100-render <job.json>     작업 파일대로 그린다
opens100-render --example      고쳐 쓸 작업 파일을 출력한다
opens100-render --help         작업 파일의 이름과 기본값
```

작업 파일의 최상위 이름은 일곱 개다: `catalogues`(제품마다 FC·PC·컨텍스트 파라미터), `datasets`, `background`, `fonts`, `view`(크기·투영·중심·축척·범위), `display`(팔레트·표시 범주·텍스트·등심선 ...), `output`(그림·바탕색·보고서). 필수는 `catalogues`, `datasets`, `output.picture`뿐이다.

AI가 쓰기 좋게 한 것:

- **모르는 이름은 오류다.** 오타가 조용히 무시되지 않는다. 메시지가 그 자리에 올 수 있는 이름을 나열한다(`view has no "sizes" (it has: size, projection, center, scale, bbox)`). 없는 컨텍스트 파라미터도 같다(카탈로그가 가진 이름을 나열한다).
- **종료 코드가 원인을 가른다.** 0 그림을 썼다, 1 파일을 못 읽었다, 2 작업 파일이 틀렸다.
- **보고서(`output.report`)**: 실제로 그려진 축척·중심·범위, 데이터셋마다 열렸는지, 설정된 컨텍스트 파라미터, 걸린 시간을 JSON으로 쓴다. `view` 없이 한 번 돌리면 데이터가 어디 있는지 알 수 있고, 그 중심으로 다음 작업을 쓴다.
- 경로는 작업 파일의 디렉터리 기준이다(실행 위치와 무관하다).
- `--example`과 `--help`가 프로그램 안에 있다: 문서가 없어도 시작할 수 있다.

## 3. 어떻게

- 라이브러리의 뷰(`CGISLibraryApp`)와 Skia 프레임(`SkiaViewFrame`)을 그대로 쓴다: 표시 설정(`ENCCommon`) → 카탈로그 → 컨텍스트 파라미터 → 팔레트 → 화면 크기 → 배경·데이터셋 → 보는 곳(`SetMap`/`SetViewMBR`/`SetScale`/`MoveMap`) → `Draw` → `WritePng`.
- JSON은 `nlohmann-json`으로 읽는다. 라이브러리의 의존성이 아니라 이 프로그램의 것이다: 저장소 `vcpkg.json`의 기능 `apps`, 포트의 기능 `apps`.
- CMake: `OPENS100_BUILD_APPS`(기본 OFF, `view-skia`가 있어야 한다). 설치하면 `bin/opens100-render`.
- 포트: 기능 `apps`(`view-skia`와 `nlohmann-json`을 끌어온다). `vcpkg_copy_tools`로 `tools/opens100/`에 놓인다(Windows에서는 필요한 DLL과 함께). 포트 판 0.2.0#2.
- Visual Studio 솔루션에는 넣지 않았다. Windows에서도 CMake(포트)로 빌드한다.
- 축척의 픽셀 크기는 라이브러리의 상수(`DOTPERCM` 38, 약 96 dpi)다. 작업 파일로 바꿀 수 없다.

## 4. 만들다 찾은 것

### 4.1 S-101 규칙에 컨텍스트 파라미터의 값이 가지 않았다 (고침)

`ProcessS101::ProcessS101_LUA`는 `InitPortrayal`로 카탈로그의 **기본값**만 규칙에 주었고, `ContextParameter::setValue`로 바꾼 값을 넘기는 코드는 주석이었다. 그래서 `SafetyContour`를 2로 두든 30으로 두든 그림이 바이트 단위로 같았다. (S-102의 격자 경로 `CoverageDataset`은 따로 넘기고 있었다.) 이제 기본값과 다른 값을 `PortrayalSetContextParameter`로 알린다. 값을 바꾸지 않은 응용(뷰어)은 전과 같다. 테스트 `RenderSmoke.AContextParameterSetOnTheCatalogueChangesTheChart`(항만 셀 `101KR00659C71`: 개관 셀 `101KR003G2M00`은 안전 등심선 2 m와 30 m의 그림이 같다).

### 4.2 회전한 뷰의 그림이 어긋난다 (고치지 않음, 프로그램에서 뺌)

`Scaler::SetRotationDegree(30)`으로 그리면 면 채움과 점 기호·수심이 서로 다르게 놓인다(수심이 육지 위에 찍힌다). 창 없이 그리는 길의 문제인지 뷰어에서도 그런지는 확인하지 않았다. 원인을 알 때까지 작업 파일에 `rotation`을 두지 않는다.

### 4.3 배경이 없는 곳은 흰색이다

데이터셋이 덮지 않는 곳은 `output.background`(기본 흰색, Dusk·Night는 검은색)다. `World.shp`는 육지만 그리므로 바다가 흰색으로 남는다. 결함이 아니라 지금의 동작이다.

## 5. 검증

- **Linux(GCC 13, 트리 안 빌드 623단계)**: `view` 없는 작업의 그림이 `opens100_view`의 것과 바이트 단위로 같다. 중심+축척(1:8000), Night·standard·텍스트 없음, 범위(`bbox`) 작업의 그림을 눈으로 확인했다. `SafetyContour` 2와 30의 그림이 다르고, `display.safetyContour: 2`의 그림은 `context.SafetyContour: 2`의 것과 바이트 단위로 같다. 틀린 작업 다섯 가지(모르는 이름, 없는 컨텍스트 파라미터, `bbox`와 `scale` 함께, JSON 아님, 파일 없음)가 종료 코드 2와 원인을 말하는 메시지로 끝난다.
- **Windows(MSVC 19.51, 포트 `opens100[core,apps]`, `x64-windows`)**: 설치 통과, `tools/opens100/opens100-render.exe`로 중심+축척 작업을 그렸다. 같은 작업의 Linux 그림과 다른 픽셀 0%(임계 16).
- **Windows 솔루션**: 4.1의 수정 뒤 Debug x64 전체 테스트 233개 중 229개 통과·4개 건너뜀, 그림 62장이 바꾸기 전과 같다. Release x64는 새 테스트를 넣기 전에 돌렸다(228개 통과, 그림 같음).
- 확인하지 않은 것: macOS, S-101 아닌 제품의 작업(S-102·S-111·S-124), 극 투영, 교환 카탈로그, CI(Skia가 없어 `apps`는 CI에 넣지 않았다).

## 6. 남은 것

- 회전(4.2)의 원인.
- 다른 제품·극 투영·교환 카탈로그의 작업 예와 확인.
- 한 프로세스가 여러 작업을 그리기(카탈로그를 한 번만 읽는다): 지금은 작업 하나에 프로세스 하나.
- 픽셀 크기(dpi)를 작업 파일로.
- 같은 방식의 다른 프로그램: 데이터셋 정보 출력, 포트레이얼 결과(`DisplayListJson`) 내보내기.
- CI에서 그림을 산출물로 남기기(Skia 빌드 시간이 걸림돌이다).
